# Design Pillars

## Inferred from aaif.dakotafabro.dev

1. Clarity first
- Fast orientation in the first screen
- Clear problem framing and clear install path

2. Growth orientation
- Language centers maturity and learning quality
- Outcomes are framed as capability building

3. Operational trust
- Explicit validation and strict checks before production use
- Workflow commands are legible and reviewable

4. Ecosystem portability
- Framework stays generic and team-owned
- Compatibility with Goose is explicit

5. Calm technical aesthetic
- Dark, focused surfaces
- Restrained accent color for hierarchy
- Readable spacing and concise structure
